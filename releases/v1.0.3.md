## 简体中文

三个实际踩到的问题：开机自启后读数先压在托盘图标上、端口列表里结束进程后不刷新、亮度面板点「刷新」窗口冻住。

### 修复

- **开机自启后读数先压在托盘图标上**：程序启动时屏幕往往还停在锁屏/登录界面，此时从像素上找到的「托盘左边界」其实是登录界面右下角的网络/电源按钮（实测 3770，真实边界 3213），而且这个错值还会被缓存 60 秒。现在先判断当前桌面是不是本进程所在的桌面——锁屏、登录界面、切换用户、UAC 期间一律不读屏幕像素；托盘边界的合理性也加了校验（窄于 80 逻辑像素的「托盘」一律不认）。
- **托盘图标还没加载完就定位**：解锁那一刻图标还在一个个往外冒，第一枪量到的只是「当时最左的那个图标」。窗口照着它贴上去之后，随后冒出来的图标正好落在窗口底下，而被窗口盖住的像素再也探测不到，窗口就卡在错误位置上。现在首次定位会先把窗口藏起来量，连续三次一致（约两秒）再显示，最多等 5 秒。
- **端口 → 进程：结束进程后列表不更新**：`TerminateProcess` 只是投递终止请求，返回时进程还在退出过程中、它的 socket 也还没关闭，紧接着枚举端口表自然还看得见那条 LISTEN。现在等进程真正退出、端口表里不再有它的 LISTEN/UDP 记录后再刷新，不用再点一次「查询」。
- **屏幕亮度：点「刷新」窗口冻住**：读亮度要碰 DDC（一块屏几百毫秒，失败还重试三次），原来在消息循环里同步做，两块屏就能把窗口冻三四秒。现在读数全部交给后台线程，每读完一块屏就先更新那一行；刷新期间窗口可以正常拖动、关闭，按钮在完成后自动恢复。

### 其他

- 「打开面板时的首次校正」和「滚轮调完亮度后的同步」也走同一条后台路径，不再有卡顿。

## English

Three problems reported in the field: the readout covering the tray icons right after boot,
the port list not refreshing after ending a process, and the brightness panel freezing on
"Refresh".

### Fixes

- **Readout covering the tray icons after auto-start at boot**: the program usually starts
  while the screen still shows the lock / logon desktop, and the "tray left edge" found from
  screen pixels there is actually the network / power buttons in the lower right corner of the
  logon screen (measured 3770 vs. the real 3213). That wrong value was then cached for 60
  seconds. The probe now first checks whether the current desktop is the one this process
  lives on — nothing is sampled from the screen while locked, at the logon screen, on user
  switch or during UAC. Tray width is also validated (anything narrower than 80 logical pixels
  is rejected).
- **Positioning before the tray icons finished loading**: right after unlocking, icons appear
  one by one, so the first measurement only sees "the leftmost icon at that moment". Once the
  window is placed against it, the icons that appear afterwards end up underneath the window —
  and pixels hidden by our own window can never be probed again. First-time positioning now
  measures with the window hidden and only shows it after three consistent samples (~2 s),
  waiting at most 5 s.
- **Port → process: list not updating after ending a process**: `TerminateProcess` only posts
  a termination request; when it returns the process is still exiting and its sockets are not
  closed yet, so enumerating the port table right away still shows that LISTEN entry. The list
  is now refreshed after the process has actually exited and its LISTEN/UDP records are gone —
  no need to press "Query" again.
- **Brightness panel freezing on "Refresh"**: reading brightness talks to DDC (hundreds of
  milliseconds per monitor, with three retries on failure) and used to run on the message
  loop, freezing the window for 3–4 seconds with two monitors. All reads now run on a
  background thread and each row is updated as soon as its monitor is done; the window stays
  draggable and closable during the refresh, and the button re-enables itself when finished.

### Other

- The first correction when opening the panel and the sync after wheel-based adjustment now
  use the same background path, so neither stutters.
